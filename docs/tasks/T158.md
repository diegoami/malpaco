# T158 Persistent computer-turn speed

- **Kind**: owner-requested feature #416; parent #422, decisions #423.
- **Branch**: `task/T158-computer-speed` · **Merge after**: T157.
- **Review**: none; presentation-only timing, owner launches milestone review.
- **Owns**: presentation speed preference/Settings, computer scheduler/feedback, associated tests, Help/manual and affected illustrations.
- **Scope**: expose persistent Slow, Normal, Fast, Very fast on launcher and in Settings. Normal is the default. Speed applies to presentation only and never enters game options/history or AI decisions. Freeze Normal action gap at 90ms (was 120) and reinforcement/attack/capture/move/raid feedback at 520/720/520/640/560ms (20% shorter). Preserve old Slow/Fast timings. Very fast uses 40ms gap and feedback. Keep old internal very-slow support for diagnostic adapters. Failed writes restore the kept preference visibly. Running games receive preference changes and new/resumed games read them. Preserve current pause/background/card-ack protections.
- **Done when**:
  1. Browser tests find exactly four public choices, default Normal, immediate selection in Settings, persistence across reload/new games, and visible write-failure rollback without match-byte changes. New cases fail before implementation.
  2. Scheduler/feedback tests verify bounded delays, ordering, cancellation and unchanged state/RNG/history when pace changes; existing timing assertions are updated only to this frozen contract.
  3. Build/root types, units and affected browser/manual checks pass; guide/Help and pictured settings updated and inspected. Integrated launcher retains viewport containment. CI green before merge; no AI policy, saved identity or published artifact changes.
- **Hazards**: do not silently change slow/fast timing, use speed as a difficulty setting, resume an explicitly background-paused game, leak listeners on game replacement, or rewrite saved matches when changing the display preference.
