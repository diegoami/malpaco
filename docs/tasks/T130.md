# T130 Bounded capture risk for current and future fronts

- **Kind**: slice of #341/#334; issue #345; branch `task/T130-capture-risk`; implement after T129/#343 merges.
- **Review**: recommended with subsequent tactical-policy adoption; owner launches any review manually.
- **Evidence**: [#339 source/model research](https://github.com/diegoami/malpaco/issues/339#issuecomment-6394494968), #340's independently checked tie-rule comparison, current single-die combat and capture rules. Precision/work bounds are [designed] computational budgets, not gameplay rules.
- **Owns**: new `src/core/computer-risk.ts`, core exports, `tests/core/computer-risk.test.ts` and evaluator documentation.
- **Scope**: From T129's public view, estimate the probability that one source captures a specified adjacent one- or two-country path, fighting until capture or unable to attack and moving the maximum legal armies after each capture. Retain one army at every source; integrate casualties across the entire path rather than multiply independent full-strength battles. Allow an explicitly supplied hypothetical reinforcement amount, without inferring hidden cards. For supported single-die, comparison-free combat, use outward-rounded millionth probability intervals, containing the model's exact probability. Bound work to 16,384 attacker/defender cells and paths to two targets. Return explicit unknown for unsupported rules, invalid/repeated/friendly/nonadjacent targets, unsafe counts or excess work; never equate unknown with zero risk. This models a specified legal tactic, not a global optimum, actual future policy, combined attacks, card effects or a policy exchange cap. No policy, UI, RNG, rules/default or save changes.
- **Done when**:
  1. `npx vitest run tests/core/computer-risk.test.ts`: independent exact rational small-path oracles contain the interval; all twelve published battle examples, defender/attacker/rerolled ties, per-capture garrisons, shared casualty budget, hypothetical reinforcement, monotonicity, land/sea paths, permutations, mutation/privacy guards, unsupported cases and work limits pass. New assertions fail before the implementation.
  2. `npm run build`, `npx tsc --noEmit -p .`, `npm test -- --maxWorkers=2` and exact-head CI pass. Existing baseline/replay/browser coverage remains unchanged; this unused evaluator helper needs no additional local browser run. Retain negative/positive output and source hashes in ignored artifacts, upload evidence and link it on #345/PR.
- **Hazards**: Floating-point probabilities violate core's integer rule. A two-hop risk must spend armies on both battles and occupation. A bounded interval is not an exact scalar or measured opponent strength.
