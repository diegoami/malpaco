# T159 Turn-widget size and hide controls

- **Kind**: owner-requested feature #417; parent #422, decisions #423.
- **Branch**: `task/T159-turn-widget` · **Merge after**: T158.
- **Review**: none; owner judges milestone screenshots.
- **Owns**: turn tracker presentation/controls, relevant layout/tests and Help/manual/illustrations.
- **Scope**: add Smaller, Larger and Hide controls, with a compact restore button while hidden. Three session-local sizes scale widget text/layout to 80%, 100%, 120%, clamped to viewport width; every control retains >=44px target. Size and hide affect only this widget, never map zoom or game state. Hide the guidance and public rows while keeping restore and contextual Resume reachable. Default is normal size and shown; new games reset it. Use existing camera resize observation so map clearance follows the visible widget.
- **Done when**:
  1. Browser checks at phone/tablet/desktop show three distinct bounded sizes, controls disable at bounds, map zoom and saved match bytes stay exact, Hide removes widget content, restore brings it back, and contextual Resume remains reachable while hidden. New cases fail before implementation.
  2. Existing guidance, public rows, phase announcements, keyboard/touch flows and camera/command containment remain valid; no control clips after rotation.
  3. Build/root types, units and affected browser/manual checks pass; instructions and affected images refreshed and inspected. CI green before merge. No rules/AI/save or published-asset changes.
- **Hazards**: do not shrink touch targets with the content, hide the only Resume path, let content render undo a hidden state, or confuse widget enlargement with map zoom.
