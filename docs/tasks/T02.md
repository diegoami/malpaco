# T02 UI gate hardening: review 006-02's seven findings

- **Kind**: correction (of the imported spike; review malpaco-godot-poc `006-ts-spike-impl-02.md`)
- **Issue**: #2 · **Branch**: `task/T02-ui-gates` · **Merge after**: T01
- **Implementer**: opencode `zai-glm-5.3-flash` (GLM-5.3 Flash on Z.AI, high), light (rule 6: code)
- **Reviewer**: opencode `gpt-6-sol` (GPT-6 Sol, high). Heavy, because these are gates that guard
  the UI (rule 6). Sol found the bypasses in a similar tool before (isle-wars-archaeology T06).
- **Why**: The owner deferred the spike's non-blocking findings to the restarted repository as its
  first tasks. Each one is a way for a broken UI to pass the tests, or a known UI defect.
- **Evidence**: review 006-02, the source of each line below; findings 2–4 were each shown passing
  all 22 tests with the defect in place.
- **Owns**: `tests/**` (the goldens included), `src/ui/**`, `src/styles.css`, `docs/spike.md`,
  `playwright.config.ts`, `.github/workflows/ci.yml` (item 8).
- **Scope** (one item per finding):
  1. **The painted-board threshold.** Measure the clean minimum match per province at both sizes,
     and record it with its margin in `docs/spike.md`. Apply the darker hatched shade only to the
     hatched seat. Set a threshold with a stated margin, and record its basis (rule 17:
     `[designed]`, measured).
  2. **A province in the wrong owner's colour must fail.** Assert each province's painted fill
     against its owner's palette colour, not against the page's own fill.
  3. **Hidden army counts and names must fail.** Add a pixel or visibility check on every badge and
     name.
  4. **"UI and engine agree" checks each dice column.** Check each column's label against its two
     dice faces under the engine's tie rule. Inverting the labels must fail.
  5. **The panel never overflows.** The zoom needs a minimum height as well as a width. Playwright
     at 1366×768, 1600×900 and 1920×1080 shows "New game" and the seed with no scrolling.
  6. **The legend matches what is drawn.** Either every legal target gets a marker, or the legend
     says when one is left out. Remove the empty band above the buttons.
  7. **The line count.** `docs/spike.md`'s core-config row says 11 lines.
  8. **Golden screenshots** (round 2; the owner's decision on #2, 2026-10-03). Sol's two reviews
     found 2 and then 3 new pixel evasions, so patching evasion by evasion does not converge. The
     look is pinned by `toHaveScreenshot` goldens instead. Items 2–5's meaningful checks stay: owner
     colours, each dice column against the tie rule, and the panel fit. The goldens cover, at both
     projects and on a fixed seed: the whole board, including the hatched seat; the result dialog,
     with its dice and verdicts; and the panel.
     - Playwright's default comparison options. No `maxDiffPixels`, `maxDiffPixelRatio` or
       `threshold` option on a `toHaveScreenshot` call, and no `expect.toHaveScreenshot` override in
       `playwright.config.ts`. Mask only content that varies run to run, and say why next to each mask.
     - **One rendering environment** (owner, 2026-10-03): goldens are made and compared in the
       official image `mcr.microsoft.com/playwright:v<version>-noble`, where `<version>` is
       `@playwright/test`'s version in `package-lock.json` (1.63.0 today). CI's Playwright steps run
       in that image. Goldens are made locally with
       `docker run --rm --ipc=host --user "$(id -u):$(id -g)" -e HOME=/tmp -v "$PWD":/work -w /work mcr.microsoft.com/playwright:v1.63.0-noble sh -c 'npm ci && npx playwright test --update-snapshots'`,
       never directly on the host. (`--user` keeps the files the worktree's owner's, not root's.)
     - Review round 2's R4: correct `docs/spike.md`'s clean label range from the instrumented run.

- **Hazards**:
  - regenerating a golden so that a defect passes: a golden changes only with its reason in the PR
    body, and the owner judges the look (5);
  - goldens made on the host, outside the image: they differ from CI's;
  - loosening a threshold until the tests pass;
  - one combined test whose failure does not say which finding broke;
  - touching `src/core` (not owned): the tie rule's labels come from `pairResults`, unchanged.
