# T108 Android background pause and safe Back routing

- **Kind**: native lifecycle; 0.3 parent #279/#271, decisions #272.
- **Issue**: #285 · **Branch**: `task/T108-android-lifecycle` · **Merge after**: T106.
- **Review**: manual 0.3 milestone review; show device evidence and limits.
- **Evidence**: owner selected save/pause on background, explicit Resume, Back closes/folds or backgrounds. T106 observed visible document state while backgrounded, paused=false, and Back navigating history. Inspect the pinned Tauri/Wry activity hooks; never edit generated sources.
- **Owns**: `src-tauri/gen/android/app/src/main/java/io/github/diegoami/malpaco/MainActivity.kt`, `src/ui/nativeGameHost.ts`, `src/ui/battleController.ts`, `src/ui/referenceBattleGame.ts`, `tests/ui/native-pause.test.ts`, `tests/e2e/native-lifecycle.spec.ts`, `tests/android/**`, `tools/android/**`, `docs/android.md`.
- **Scope**: Bridge Android activity background/foreground and Back to the bundled frontend with minimal native capabilities. Preserve a native resume-required flag across background/restart. Background pauses before further scheduled computer actions and force-keeps the current ordinary replay, including a partial computer turn, using existing storage; T109 (#286) supplies durable native game-data storage separately. Returning never unpauses. Dialog-close callbacks cannot release a background pause; only explicit Resume can. Back dismisses an open dialog or optional card, folds a required choice without confirming it, otherwise backgrounds the map; never navigate WebView history or give up. Bind/unbind each host, handle startup while inactive and preserve paused games across rotation/replacement. No core, game RNG, rules identity, gameplay action or external dependency changes.
- **Done when**:
  1. `npx vitest run tests/ui/native-pause.test.ts`: background pause blocks temporary resume, repeated events are inert, explicit resume releases it and disposal/replacement never revive callbacks. New behavior assertions fail on the base.
  2. `npx playwright test tests/e2e/native-lifecycle.spec.ts --workers=2` in the pinned image: bridge-controlled background during computer play force-keeps the exact current game; later clock advances/foreground do not act; dialogs, menu and pending capture handle Back without history/engine changes; explicit Resume alone restarts play.
  3. `node tools/android/lifecycle-smoke.mjs --apk <recorded-apk> --serial <device>`: real Android Home/Back/return, pending choice, rotation and restart prove the same policy with device/API/WebView identities, replay and screenshots. Build/source/APK hashes are retained under artifacts/ and linked on #285.
  4. `npm test`, `npm run build`, `npx tsc --noEmit -p .`, affected pinned browser specs, `git diff --check`, native build CI and web CI pass.
- **Hazards**: A synthetic browser event cannot prove Kotlin wiring; actual device checks are required. No automatic resume from Help/Settings close. Native data failure/recovery and signed update guarantees belong to T109, not this lifecycle test.
