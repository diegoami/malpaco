# T103 Guided play: Fight or Move beside the selected country, combat after the last army, a hint when you hesitate

- **Kind**: feature (0.2.1)
- **Issue**: #261 · **Branch**: the session branch · **Merge after**: the #260 fix
- **Review**: none per PR; the 0.2.1 milestone review (#253) covers it, on the moved candidate.
- **Evidence**: the owner, 2026-10-22, while playing the candidate: "Show the pulsing arrow after a delay when it seems that the player does not know what to do"; then "maybe it is better not to autoselect anything … The issue in the original game was that the fight and move buttons appeared next to the province you selected. So we should find a way to have a fight and move icon appear next to a province … that you selected, from where you can attack and if not, from where you can move armies. Leave the attack and move icons where they are"; then "after placing all the armies … preselect fight either way, as if the user had clicked on fight" (the crossed-swords Start combat). [designed] throughout.
- **Owns**: `src/ui/referenceBattleGame.ts`, `src/ui/battleChrome.ts`, `src/ui/battleView.ts`, new `src/ui/provinceAction.ts` and `src/ui/hesitationHint.ts`, `src/styles.css`, `src/ui/help.ts`, `docs/play.md`, `tools/release/PLAY.md`, `docs/releases/0.2.1/ACCEPTANCE.md` (a line), `tests/e2e/guided-taps.spec.ts`, and the existing specs the change makes wrong.
- **Scope** (the player's game):
  - **Beside the selected country**, in the attack phase, one action button follows its count through pans, zooms and rotations:
    - **Fight** when the country can attack: off until an enemy target is chosen, then one press is one exchange, exactly like the card's Fight;
    - else **Move** when it can move armies: a press starts the friendly move from that country;
    - else nothing. A tap on a country only selects it; nothing acts without a press.
    - The corner and card controls (Fight, Move armies, End turn) stay where they are.
  - **The last army starts combat:** placing the last army of the pool ends placement by itself, as if Start combat were pressed (the same engine action).
  - **A pulsing hint when you hesitate:** after a pause with no input on your own turn, a small arrow pulses next to Fight (an attacker and a target chosen) or Confirm (a capture or a move waiting for its amount). It disappears at the next input, never shows during a computer turn or while paused, and is presentation only (`aria-hidden`).
- **Done when**:
  1. `npx playwright test tests/e2e/guided-taps.spec.ts --workers=2` at 390×844 and 1280×800 shows:
     - Fight beside a country that can attack (off until a target, then one press is one exchange by the engine oracle), Move beside one that can only move (a press opens the move from it), nothing beside one with neither; taps alone change nothing in the saved match;
     - the last placed army starts combat (one `endReinforcement`), and the Start combat control is gone;
     - after the delay with no input the arrow points at Fight and at Confirm, and is gone after the next input, while paused and during a computer turn; never before the delay.
  2. `npm test && npm run build` pass; existing specs migrate without weakening an assertion.
- **Hazards**:
  - **The delay is [designed]** (about 4 s); tests use the page clock, never real waiting.
  - **Never act for the player.** A tap only selects; nothing rolls or moves armies without the player's own Fight or Confirm. Ending placement after the last army is the one automatic step, and it moves no armies.
