# T103 Fight and Move on the selected country; combat after the last army

- **Kind**: feature (0.2.1)
- **Issue**: #261 · **Branch**: the session branch · **Merge after**: the #260 fix
- **Review**: none per PR; the 0.2.1 milestone review (#253) covers it, on the moved candidate.
- **Evidence**: the owner, 2026-10-22, while playing the candidate: "Show the pulsing arrow after a delay when it seems that the player does not know what to do"; then "maybe it is better not to autoselect anything … The issue in the original game was that the fight and move buttons appeared next to the province you selected. So we should find a way to have a fight and move icon appear next to a province … that you selected, from where you can attack and if not, from where you can move armies. Leave the attack and move icons where they are"; then "after placing all the armies … preselect fight either way, as if the user had clicked on fight" (the crossed-swords Start combat); then "Forget the pulsing arrows … place armies, user selects province from where to attack, fight button appears from province, user clicks fight, user picks target province, a fighting round happens. The icon is still there, if he click on it there is another fighting round … When the user clicks on a province from which no attack is possible, the move icon appears in the province, the user clicks on it, then picks the target province to move to. The bar for choosing how many armies to move should always move next to the province"; "The ghost card should not be visible if there is no action there to be done"; "when selecting a country to move on, and then clicking on move, the country I selected first should stay selected". [designed] throughout.
- **Owns**: `src/ui/referenceBattleGame.ts`, `src/ui/battleChrome.ts`, `src/ui/battleView.ts`, new `src/ui/provinceAction.ts`, `src/styles.css`, `src/ui/help.ts`, `docs/play.md`, `tools/release/PLAY.md`, `docs/releases/0.2.1/ACCEPTANCE.md` (a line), `tests/e2e/guided-taps.spec.ts`, and the existing specs the change makes wrong.
- **Scope** (the player's game):
  - **On the selected country**, in the attack phase, one action button follows its count through pans, zooms and rotations:
    - **Fight** when the country can attack: a press arms it; the next enemy neighbour tapped is fought at once, one round; a press with that target chosen is another round. Selecting another country moves the icon there, unarmed.
    - else **Move** when it can move armies: a press starts the friendly move from it; tap where to.
    - else nothing. A tap on a country only selects it.
    - The corner and card controls (Move armies, End turn, the card's Fight and Cancel) stay where they are; Move armies keeps the selected country as the source when it can be one.
  - **Amount bars beside their country:** the −/amount/+ bar of a capture and of a friendly move rests beside that country's count and follows the camera.
  - **No empty card:** an attack card whose pair can no longer fight (only Cancel left) closes.
  - **The last army starts combat:** placing the last army of the pool ends placement by itself, as if Start combat were pressed (the same engine action).
- **Done when**:
  1. `npx playwright test tests/e2e/guided-taps.spec.ts --workers=2` at 390×844 and 1280×800 shows, against the engine:
     - Fight on a country that can attack: a press arms it and changes nothing; a tapped enemy is one round; a second press is another round; selecting another country moves the icon there, unarmed;
     - Move on a country that cannot attack: a press opens the move; the tapped destination opens the amount bar beside its count; nothing changes until Confirm;
     - a capture's amount bar beside the captured country;
     - Move armies keeps the selected source; after a capture, no card stays open with only Cancel;
     - the last placed army starts combat (one `endReinforcement`), and the Start combat control is gone.
  2. `npm test && npm run build` pass; existing specs migrate without weakening an assertion.
- **Hazards**:
  - **Never act for the player unasked.** A tap only selects, except an enemy tap after the player armed Fight, which is the round they asked for; nothing moves armies without Confirm. Ending placement after the last army is the one automatic step, and it moves no armies.
