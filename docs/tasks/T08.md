# T08 Shared combat rules: single exchanges, fair ties, no forfeit

- **Kind**: feature
- **Issue**: #30 · **Branch**: `task/T08-shared-combat` · **Merge after**: T07
- **Implementer**: owner-selected OpenAI GPT-6 Luna subagent in Codex; isolated worktree (rule 6.1).
- **Reviewer**: chosen separately by the owner, outside the implementer's and session's families (rule 6.2).
- **Evidence**: [promoted core design](https://github.com/diegoami/isle-wars-archaeology/blob/main/design/core-rules.md), Combat and Ownership change: decisions 7/11, C-CMB-01..11, C-OWN-01. Only reviewed behaviour/design passes here (rules 17/19).
- **Owns**: `src/core/combat.ts`, `src/core/state.ts`, `src/core/types.ts`, `src/core/setup.ts`, `src/core/index.ts`; `tests/core/malpaco-combat.test.ts` (new), `tests/core/setup.test.ts`; `docs/spike.md`, `RUN-NOTES.md`.
- **Scope**: export `malpacoRules()` and use it as `createGame`'s default. Keep explicit custom rules, `classicRules()`, legacy `newGame`, and spike UI behaviour compatible. Standard malpaco combat requires an owned source, neighbouring enemy and at least 2 armies; defender strength and seat kind/difficulty never restrict it. Each action: one six-sided die each, reroll ties until unequal, loser loses one army. An attacker reduced to 1 keeps its country and attack phase. Capture defaults to moving all remaining armies except one, without clipping; preserve centres. Choosing capture quantities, UI integration, income, movement and victory redesign are later chunks. Cite rule constants.
- **Done when**:
  1. `npx vitest run tests/core/malpaco-combat.test.ts tests/core/setup.test.ts` passes; new acceptance tests fail before implementation. Generated games select the new preset; explicit custom rules and existing legacy tests retain their behaviour.
  2. The suite refuses attacks from unowned or missing sources.
  3. It refuses friendly or missing targets.
  4. It refuses non-neighbours.
  5. It refuses non-attack phases.
  6. It allows 2 versus 2000, refuses 1, and gives identical rules/results to humans and Easy/Normal/Hard computers.
  7. Scripted repeated ties consume all draws before one decisive exchange; either side loses exactly 1.
  8. A losing attacker retains ownership, 1 army and attack phase.
  9. Capture moves all but one, conserves surviving armies above 999, preserves centres, and cannot mutate input.
  10. Seeded states reproduce and resume RNG after ties; computer streams remain unchanged.
  11. Mutations of each legality guard, minimum, strength gate, dice count, ties, forfeit and capture amount fail targeted tests, then are restored.
  12. `npm ci && npm run build && npx vitest run && npx playwright test` passes, including purity. `git diff --exit-code origin/main -- src/ui tests/e2e data/maps/archipelago.json` exits 0; no golden changes. Document compatibility.
- **Hazards**: changing Classic expectations; allowing a tie to cause losses; ending the phase on failure; clipping large captures; using computer RNG for combat; weakening assertions (rule 5).
