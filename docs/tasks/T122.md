# T122 Atomic Android snapshot primitive

- **Kind**: native durability foundation; first bounded slice of T109/#286, parent #271.
- **Issue**: #314 · **Branch**: `task/T122-native-snapshot` · **Depends on**: T108.
- **Evidence**: #286 requires app-private atomic snapshots before frontend hydration. Android's [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile) requires caller locking; commit errors must be detected rather than inferred from a completed call.
- **Owns**: application-owned Android snapshot class, isolated Android instrumentation tests, native test runner/configuration, `tools/android/test-snapshot.mjs`, `docs/android.md`.
- **Scope**: Serialize all store instances in this process. Accept one UTF-8 JSON envelope `{version:1,entries:{...}}`, with string-valued `malpaco:*` keys; keep game/meta/scoreboard/preferences/positions/settings values opaque, including malformed or future game records. Validate strict envelope shape and a designed16MiB byte bound before writing. Use fixed current/previous/recovery files below the app's private files directory, never a caller-selected path. Atomically replace and verify committed bytes; failed writes retain the last good image. Recover interrupted writes and a valid prior image, preserving malformed original bytes before repair. A different existing recovery image or unsupported envelope blocks destructive replacement with a typed error. Add no frontend bridge, startup/hydration change, rule/RNG/save identity change or production signing; #286 retains those integration/upgrade obligations.
- **Done when**:
  1. `node tools/android/test-snapshot.mjs --serial <dedicated-emulator>` proves exact Unicode/control-character/opaque-record round trips across new instances; coherent game+meta/config images; invalid, oversize and failed writes preserve good bytes; interrupted writes recover; malformed/unsupported originals survive; concurrent instances serialize; namespace keys cannot select paths. Behavioral failures are retained against a minimal direct-write baseline before the atomic implementation.
  2. The runner builds the source's x86-64 debug APK and instrumentation APK, installs with data-preserving updates and runs isolated test contexts without clearing/uninstalling app data. Its report retains source/asset/APK hashes, API/device/WebView identity and complete failures. No physical-device or power-loss claim is inferred from this emulator proof.
  3. Build/full types/units, `git diff --check`, web CI and Android build CI pass. Evidence reaches Drive and the issue. Frontend hydration, serialized namespace commits, visible recovery and same-signed update acceptance remain separate bounded contracts under #286.
