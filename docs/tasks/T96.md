# T96 Instant start: no setup, one human against three computers, New game, resume on refresh

- **Kind**: feature (0.2.1)
- **Issue**: #245 · **Branch**: the session branch · **Merge after**: T90
- **Review**: none per PR; the 0.2.1 milestone review covers it (#244 Q11).
- **Evidence**: owner decisions on #240 and #244 (2026-10-22). [designed] throughout: no archaeology question.
- **Owns**: `src/main.ts`, `src/ui/geographicGame.ts`, `src/ui/referenceBattleGame.ts`, `src/ui/battleChrome.ts`, `src/ui/victoryView.ts`, `src/ui/referenceMatchFiles.ts`, `src/styles.css`, `docs/play.md`, `tools/release/PLAY.md`, `tests/e2e/instant-start.spec.ts`, and the existing specs the change makes wrong.
- **Scope**: Opening the root page starts a game at once on a random seed, with one human against three Normal computers, Domination on and no round limit. Place names are By seed. There is no setup screen.
  - `?seed=N` fixes the seed, as a hidden route for tests and bug reports. `?view=reference-game` keeps the Nine Isles board, also hidden.
  - **New game** in the menu asks "Give up this game?". Yes shows the result card, and its New game starts a fresh random game. During the result it starts at once.
  - Save game and Load game leave the player's UI, and version-1 loading goes with them (0.2.0's A13 is retired).
  - The current match is kept in `localStorage` (its versioned save text) after every action. A refresh resumes it exactly, while a finished, given-up or corrupt record starts a fresh game.
  - Out of scope: the cards and menu trimming (T97).
- **Done when**:
  1. `npx playwright test tests/e2e/instant-start.spec.ts --workers=2`. It must show:
     - the root page shows a map with 46 countries and no setup form;
     - four seats: one human and three computers;
     - two loads give different seeds, while `?seed=7` gives seed 7;
     - no Save or Load control in the page;
     - after some actions a reload resumes the identical match: the same history and RNG, read through a page hook in tests only, or through `localStorage`;
     - New game asks, then shows the result, then starts a different seed;
     - a corrupt stored record starts a fresh game without an error;
     - `?view=reference-game` still opens Nine Isles.
  2. `npm test && npm run build` pass; existing specs that drove setup or files use the hidden routes or their own fixtures, and no assertion is weakened.
- **Hazards**:
  - **Tests need deterministic games.** Keep a test-only way to start from a fixture (`?seed`, plus loading a fixture through the hidden route or a test hook) rather than deleting the file code they rely on.
  - **The stored record is the versioned save text.** Never store a raw state: replay checks still apply on resume.
  - **Never resume into a different build's incompatible save silently.** On a parse or replay error, start fresh.
