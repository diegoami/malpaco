# T152 Persistent button labels and responsive action sizing

- **Kind**: owner-requested UI correction, #401; 0.5.1.
- **Issue**: #401 · **Branch**: `task/T152-button-labels`.
- **Review**: none; owner judges screenshot clarity. No publication included.
- **Evidence**: owner requests Icons/Text on the start screen and in Settings, smaller responsive button labels, and no mid-game conversion of Attack/Move into icons. Current `data-both` rendering forces glyphs, while CSS fixes the text action to a 120px minimum.
- **Owns**: UI display-preference storage, launcher/settings, command decoration, map action rendering/layout/CSS, relevant unit/browser tests, Help/manual and curated screenshots.
- **Scope**: Store a browser-wide Icons/Text display preference independently of game options/rules. Offer it on the launcher and in-game Settings; apply it immediately and keep it across turns, new games, reloads and viewport changes. Use Text by default unless the owner chooses otherwise before implementation. Action commands, including simultaneous map Attack/Move, obey it consistently; standard utility/amount/close symbols and country/card content retain their meanings. Scale command text and padding with viewport width/height instead of oversized fixed map labels, retaining at least 44px touch targets. Keep legal actions, map anchoring, exact saved match bytes and all rules/AI unchanged. Correct related blank command glyph styling (#400) if reproduced in this same presentation path.
- **Done when**:
  1. Controlled browser tests show the setting at start and during play, immediate changes, persistence across reload/new game and unchanged saved match bytes/rules. A failed preference write visibly restores the kept selection without affecting play.
  2. Real single- and dual-action map states keep Text or Icons across source/target changes and resizes. Text font/footprint is smaller on a phone than desktop, controls fit the viewport and retain >=44px hit targets. Icon shapes are visible and named. New checks fail before implementation and pass after.
  3. Build/root types, units and changed/affected browser specs pass; full extracted-playable CI passes before merge. Phone/landscape/desktop screenshots and refreshed manual examples are inspected for clipping/overlap; Help explains this immediate display preference versus next-game rules. Published assets remain unchanged.
- **Hazards**: A content redraw or mutation observer must not erase labels/glyphs or multiply observers across game replacement. Preference changes must never dispatch game actions or rewrite immutable match identities. Do not weaken existing behavioral or accessibility checks to accommodate the new mode.
