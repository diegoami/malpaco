- **Kind**: release preparation, requested by the owner after the usability fixes.
- **Issue**: #391; scope #381. **Branch**: `task/T149-release-0.5.0`.
- **Owns**: `package.json`, root package-lock version entries,
  `docs/releases/0.5.0/RELEASE-NOTES.md` and `ACCEPTANCE.md`.
- **Scope**: prepare a reviewable release PR with version 0.5.0 and the exact

  automatic reviewer, tag, external release upload or production deployment.

  2. Release notes and acceptance protocol cover T144–T148, including both legal

  3. PRs #387, #380, #388, #389 and #390 are merged with their checks satisfied;
     the final integrated source passes build/types/units and exact-candidate

     decisions in a milestone-review issue. The owner launches the review;
     publication waits for the verdict, visual acceptance and explicit go-ahead.
- **Hazards**: a preparation build is not a complete or accepted candidate while
  feature PRs remain open. Preserve published tags/assets and distinguish local
  test evidence from final candidate CI. Do not weaken checks to clear the gate.
