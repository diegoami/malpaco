# T09 Island income: the complete-island bonus as pure functions

- **Kind**: feature
- **Issue**: #23 · **Branch**: `task/T09-island-income` · **Merge after**: —
- **Implementer**: an OpenCode session on the owner's other computer, on its own checkout (owner's
  dispatch decision, 2026-10-13 — in place of the usual rule-6.1 subagent question). Its PR carries
  a `model:` label, so `review.mjs` excludes that family from the review.
- **Reviewer**: chosen at the rule-6.2 question before review. Both the implementer's family
  (openai) and this session's (glm) are excluded; propose MiMo v2.6 Pro (`opencode_go`).
- **Evidence**: isle-wars-archaeology `spec/island-bonuses.md`, cited as claims only (rule 19):
  C-BON-01 (an island pays only when every one of its countries is held; partial control earns
  nothing; several complete islands sum with no diminishing and no set-of-islands extra; the
  on-board message reports the count of islands held, not their values), C-BON-02 (the values).
  The values already exist: `Island.bonus` on the authored map (`data/maps/archipelago.json`) and
  the generator's [designed] formula in `src/core/board-gen.ts`. This task adds no constant.
- **Owns**: `src/core/bonuses.ts` (new), `tests/core/bonuses.test.ts` (new), `src/core/index.ts`
  (one export line).
- **Scope**: a pure function — suggested shape `islandIncome(state, seatId) → { islands, total,
  count }`, the seat's completely-held islands and the sum of their bonuses, plus the count (the
  future message reports the count, not values). No wall clock, no random, no DOM (rule 18). Out
  of scope: changing any bonus value or the generator; wiring into the turn sequence (the
  reinforcement task owns that); any UI.
- **Done when**:
  1. `npx vitest run tests/core/bonuses.test.ts` exits 0, with cases: a seat owning every province
     of an island earns exactly that island's `bonus`; one province of the island owned by another
     seat → that island pays that seat 0; two held islands pay their sum; no held islands →
     `total` 0, `count` 0.
  2. The function is exported from `src/core/index.ts` and gives the same answer twice for the
     same inputs, on the authored map and on a `generateBoard` result.
  3. Deletion mutation: removing the all-provinces-complete check turns the suite red; restored,
     green again. Name the deleted line.
  4. `npm test` and `npm run build` are green.
- **Hazards**: recomputing a bonus from island size (read `Island.bonus`; the size formula is
  board-gen's, not this task's); paying an island whose provinces are split across seats;
  importing DOM or I/O into `src/core` (the purity test fails it).
