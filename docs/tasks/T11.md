# T11 Reinforcement phase: a pool players can spend before attacking

- **Kind**: feature
- **Issue**: #32 · **Branch**: `task/T11-reinforcement-phase` · **Merge after**: T08, T10
- **Implementer**: chosen at the rule-6.1 question; recorded before dispatch.
- **Reviewer**: chosen at the rule-6.2 question; never the implementer's family.
- **Evidence**: T10 and `src/core/reinforcement.ts` supply the income formula and its
  provenance. Turn ordering and placement are `[designed]`: inspected the existing
  `types.ts`, `rules.ts`, `state.ts` and `setup.ts`; these implement only the spike's
  attack/end-turn shortcut, with no placement contract. This first playable slice
  grants income before each living seat's attack phase, including its first turn.
- **Owns**: `src/core/{types,rules,state,setup,index}.ts`, a new core turn module if
  needed, `tests/core/**`, and the affected descriptions in `docs/spike.md`.
- **Scope**: Add a reinforcement phase and remaining pool to the Malpaco turn
  sequence. At turn entry calculate T10 income exactly once. A placement action
  (`{ kind: "reinforce", province, amount }`) spends a positive integer quantity
  from `reinforcementPool` on an active seat's owned province; reject
  unknown/enemy provinces, invalid quantities and overspending without mutation.
  Phase `"reinforce"` advances via `{ kind: "endReinforcement" }` only when the pool is empty. Ending
  combat passes to the next living seat and grants its income once. Preserve the
  legacy Classic sequence through an explicit ruleset setting/default, so the
  existing screen remains usable until T12. Generated Malpaco games use the new
  sequence. Clone and action history include new state/actions. Redeployment,
  centres, hazards, cards and save/replay are later tasks.
- **Done when**:
  1. `npx vitest run tests/core/turns.test.ts` exits 0: initial Malpaco pool equals
     T10 income; owned placement adds/spends exactly the requested amount;
     zero/negative/fractional/nonfinite quantities, unknown/enemy provinces,
     overspending and wrong-phase actions fail without changing input or RNG.
  2. `npx vitest run tests/core/turns.test.ts` proves premature combat/turn ending is refused; exhausting
     the pool permits combat; repeated advance cannot award income again;
     ending combat skips eliminated seats, advances rounds correctly and grants
     the next seat's income once; finished games refuse actions; Classic retains
     its old turn sequence. Exercise generated and authored maps.
  3. Mutation checks in the implementation report name the changed lines and
     failing tests for removed ownership, pool and phase checks; restored, green.
  4. `npm test` and `npm run build` pass; existing combat/setup assertions are
     updated only where this task intentionally changes the Malpaco entry phase.
- **Hazards**: T10 gives an eliminated seat minimum income; skip that seat before
  calling it. Keep phase progression independent of preset ids. Preserve seeded
  setup draws and immutable `apply`; placement consumes no randomness.
