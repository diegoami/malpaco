# T06 Bundled UI font: rendering independent of the host

- **Kind**: infrastructure
- **Issue**: #21 · **Branch**: `task/T06-bundled-font` · **Merge after**: —
- **Implementer**: the `implementer` subagent on haiku (the owner's choice, 2026-10-13).
- **Reviewer**: `reviewer.default` (GPT-5.6 Luna), unless the owner picks another at the rule-6.2 question.
- **Evidence**: on 2026-10-13 the six golden tests in `tests/e2e/slice.spec.ts` (board, panel and
  result dialog, at 1280x800 and 1920x1080) failed on a clean `origin/main` in WSL and passed in CI
  (run 38383925425, a1a522d). The diff images differ only in text glyphs: the CSS asks for
  `system-ui, sans-serif` and no font ships with the project, so the browser uses the host's fonts
  (DejaVu Sans on WSL). T02 item 8 already pins one rendering environment, the official Playwright
  image, and WSL has no Docker.
- **Owns**: `src/styles.css`, `index.html`, `public/fonts/**` (or the path Vite serves static
  assets from), `tests/e2e/slice.spec.ts-snapshots/**`, `docs/tasks/T06.md`'s own PR notes.
  No `src/core/**`, no change to any test's logic or to its comparison options.
- **Scope**:
  1. Add **Inter** (SIL Open Font License; the variable font, or the weights the CSS uses: 600, 700
     and 800 plus the regular body weight) as files in the repository, with its licence text
     beside them. Take the files from Inter's official release, and record the version and URL in
     the PR (rule 19: an open font, not anything from the original game).
  2. Declare it with `@font-face` (`font-display: block`, so a screenshot never captures a
     fallback), and put it first in every `font` and `font-family` stack in `src/styles.css` and
     `index.html`, keeping `system-ui, sans-serif` after it as the fallback.
  3. The page must not paint before the font is ready in the golden tests: wait for
     `document.fonts.ready` before each screenshot, in the shared helper the goldens already use.
     Do not add `maxDiffPixels`, `maxDiffPixelRatio` or `threshold` (T02 item 8).
  4. Regenerate the six goldens. The authority is CI's image (T02 item 8). If Docker is not
     available, regenerate them from a CI run's `playwright-report` artifact, never from the host.
     The owner judges the look from the new screenshots (rule 20).
  Out of scope: any layout change, any colour or size change, any other font.
- **Done when**:
  1. `git ls-files public/fonts` (or the chosen folder) lists Inter's font file(s) and its OFL
     licence; `grep -rn "system-ui" src/styles.css index.html` shows every stack with Inter before it.
  2. `npx playwright test tests/e2e/slice.spec.ts` passes in CI with the regenerated goldens, and
     the PR links that run.
  3. The six golden files changed and no other file under `tests/e2e/` did, apart from the shared
     screenshot helper's `document.fonts.ready` wait.
  4. Removing the `@font-face` rule makes the golden tests fail (applied, run and restored, with
     the failing output in the PR body, rule 9).
  5. `npm ci && npm run build && npx vitest run` is green.
  6. Informational, not blocking: the same Playwright run on a WSL host, with its result in the
     PR. If it still differs, say by how many pixels.
- **Hazards**: regenerating the goldens on the host would pin them to WSL's renderer and turn CI
  red; never do that. A fallback font in a screenshot would pass or fail by accident, so `font-display`
  and the `fonts.ready` wait are not optional. The font file counts toward the repository's size;
  prefer a subset or a single variable file over every weight.
