  ### The 5 fairness checks (pure, unchanged from the design)

  Each check takes a `GameMap` and returns the list of violations (an empty
  list means the check passes):

  1. **Bonus out of proportion**: any island whose `bonus > size` (a small
     rich island, however the bonus got there). Cites C-BRD-01.
  2. **Fortress**: any island of size ≥ 7 with exactly one country carrying a
     sea lane (a "single-entrance" island that size can be held by one
     country), **or** more than 3 islands (any size) with a single entrance.
     "Single-entrance" = an island where exactly one of its countries has a
     non-empty `seaLanes` list. Cites C-BRD-01.
  3. **Easy bonuses concentrated**: the sum of `bonus` over the single-
     entrance islands is more than a quarter of the sum of all `bonus`.
     Cites C-BRD-01.
  4. **Remote / hub island**: in the island graph (vertices = islands, edges
     = pairs where at least one country of one has a sea lane to a country
     of the other), any island with eccentricity > 4 (more than 4 crossings
     from some other island) or degree > 4 (touching more than 4 others).
     Cites C-BRD-01.
  5. **Crowded crossing country**: any country with more than 2 sea lanes.
     Cites C-BRD-01.

  ### Generator structural constraints (the amendment)

  The T05a generator's Phase 2 (random fill of the 16 crossings) had no
  per-country, per-island, or island-graph constraints, so 996/1000 boards
  failed check 5 and 758/1000 failed check 4. The amendment adds four
  **named, exported constants** to `src/core/board-gen.ts`, each citing
  `C-BRD-01` next to its declaration, and enforces them in Phase 2 (and, where
  needed, in Phase 1's spanning tree):

  1. **`MAX_LANES_PER_COUNTRY = 2`** — a country carries at most 2 sea
     lanes. Phase 2 must skip any candidate pair where either endpoint
     already has 2 lanes. Cites C-BRD-01.
  2. **`MAX_ENTRANCES_BY_SIZE: Record<size, max>`** — per-island cap on the
     number of distinct countries that may have a sea lane. The cap is
     derived from C-BON-02 so that `bonus = max(2, floor(size/2) + entrances)
     ≤ size` always holds: for size 3 → 2, size 5 → 3, size 7 → 4, size 10
     → 5. Phase 2 must skip any candidate where the destination island would
     exceed its cap. Cites C-BRD-01, C-BON-02.
  3. **`MIN_ENTRANCES_PER_ISLAND = 2`** — every island must have at least 2
     countries with a sea lane (anti-fortress). Phase 1's spanning tree
     must place at least one lane on each island, and Phase 2 must keep
     adding lanes until every island meets the minimum. Cites C-BRD-01.
  4. **`MAX_ISLAND_GRAPH_DEGREE = 4`** — in the island graph, no island may
     have degree > 4. Phase 2 must skip any candidate where the resulting
     degree of either endpoint would exceed the cap. Cites C-BRD-01.

  These are the structural preconditions the 5 checks require. Together with
  the existing T05a `BORDER_MAX = DEGREE_MAX - 1` headroom reservation, they
  define the generator's full invariant set. They are **exposed and tested**:
  each has a rule-9 mutation in the PR body that breaks the suite when
  changed.

  ### The retry loop and the "attempts run out" behaviour (unchanged)

  The retry loop calls the T05a generator body (now with the structural
  constraints in Phase 2), runs the 5 checks on the result, and rejects when
  any check returns a non-empty list. **The cap is a named, exported
  constant** `MAX_BOARD_ATTEMPTS` (e.g. 50; the implementer picks the
  smallest number that, on a 200-seed sweep, gives a success rate ≥ 99% —
  the value is fixed by a test, not by an implementation detail). The retry
  consumes the `DeterministicRng` between attempts, so each attempt draws a
  different plan; the generator never re-uses the same plan twice in a row.

  When the cap is reached, `generateBoard(seed)` returns
  `{ ok: false, errors: ["fairness checks failed after N attempts: …"] }` —
  the `ok: false` branch is already part of the public type. **Falling back
  to T03's `archipelago.json` is not in scope** (T03 is a single board, not a
  per-seed fallback; the design's parenthetical "for example" is one option,
  not a mandate, and a per-seed curated set is a different feature). If the
  design team later wants a per-seed fallback, that is its own task.

  ### Tests

  The 5 `test.skip` placeholders in `tests/core/board-gen.test.ts` (T05a's
  mechanical migration) are replaced with real tests that run the 5 check
  functions on the generator's output and assert no violations. A
  `tests/core/board-fairness.test.ts` adds synthetic-map tests for each
  check: a hand-built `GameMap` that violates only that one check, asserting
  the check catches it and the other four pass on a hand-built valid board.
  Plus a wide-seed sweep (≥ 200 seeds) that confirms the success rate is
  ≥ 99% within `MAX_BOARD_ATTEMPTS`.

- **Hazards**:
  - **Weakening a check to make generation easier.** The design says don't;
    the amendment reinforces this — the fix lives in the generator, not in
    the checks. If the implementer proposes a weakened check, stop and
    report.
  - **A retry loop that draws the same plan twice.** Consume the
    `DeterministicRng` between attempts, not just the state — a new plan is
    only new if the rng advanced past the prior draw sequence.
  - **Forgetting to enforce the constraints in Phase 1's spanning tree**, not
    just Phase 2. `MIN_ENTRANCES_PER_ISLAND = 2` requires at least one
    lane on every island in Phase 1; `MAX_ISLAND_GRAPH_DEGREE = 4` may
    require Phase 1 to skip island pairs whose degree would exceed the cap.
  - **Allowing per-island lane count to creep up via Phase 1 + Phase 2
    combined.** The cap is the total per island, not per phase.
  - **A hand-built map that happens to also violate another check** in the
    synthetic-map tests. Each test's "violates only this check" map must
    pass the other 4; build them carefully, assert both directions.
  - **Confusing "single entrance"** (one country with sea lanes) with
    "exactly one sea lane" (which would be a country-level count, not an
    island-level property). The design means the former.
  - **Returning `{ ok: false }` for a structurally invalid board** that should
    not have been generated in the first place. The T05a generator already
    guarantees structural validity; `ok: false` is reserved for fairness
    exhaustion after the structural constraints are in.
  - **Falling back to T03's `archipelago.json`** (a single board, not a per-
    seed fallback). The task explicitly rules this out; report the design
    change as a follow-up if the cap is too tight.
  - **Coupling the deal.** T05b still returns a `GameMap`, not a `GameState`;
    T06 wires the generator to the game stream.
  - **Reading the time** ("X attempts took Y ms; if too slow, fail"). The
    cap is a count, not a duration; rule 18 forbids wall-clock.
  - **Decorative rule-9 transcripts.** The T05a round 1 mutation was
    decorative because the test mirrored the bug; the implementer must run
    each mutation and quote the actual failing-then-passing output.
