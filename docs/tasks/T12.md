# T12 Playable reinforcement controls and Malpaco combat

- **Kind**: feature
- **Issue**: #33 · **Branch**: `task/T12-reinforcement-ui` · **Merge after**: T11
- **Implementer**: chosen at the rule-6.1 question; recorded before dispatch.
- **Reviewer**: chosen at the rule-6.2 question; never the implementer's family.
- **Evidence**: T11's turn contract, T08's Malpaco combat and T10 income. Placement
  interaction is `[designed]`: inspected `src/ui/app.ts` and `panel.ts`; the spike
  offers selection, Attack and End turn, with no placement controls.
- **Owns**: `src/ui/**`, `src/styles.css`, `tests/e2e/**`, and affected descriptions
  in `docs/spike.md`. Keep the authored board for this milestone.
- **Scope**: Start the two-human screen with `malpacoRules()`. Display current
  phase, province base, island income and remaining pool. During reinforcement,
  clicking an owned province places one army through the core action; enemy
  clicks spend nothing. Provide a clearly labelled transition to combat, disabled
  until the pool is empty. Combat retains province selection, legal targets and
  the result dialog, using T08 exchanges. End combat passes to the next seat's
  reinforcement phase and clears obsolete selection. Explain the current action
  in visible hints and accessible controls. Generated-board integration, setup
  options, redeployment and save controls are later tasks.
- **Done when**:
  1. `npx playwright test tests/e2e/reinforcement.spec.ts` passes at both configured
     sizes: page loads with a painted board and visible income/pool; enemy clicks
     do not spend; each owned click visibly increases armies and reduces pool;
     combat is unavailable until placement completes; transition enables an
     actual attack and readable result; end combat shows the next seat's new
     pool. Drive all actions through normal UI clicks, with no state injection.
  2. The same suite completes placement and combat transitions for both seats,
     returns to the first seat in the next round, and checks no page/console
     errors. A mutation removing the placement handler makes it fail; report it.
  3. `npx playwright test` passes in the pinned Playwright image. Update existing
     flows for reinforcement and single-die combat; regenerate affected goldens
     only in that image, preserving independent painted/readability checks.
  4. `npm test` and `npm run build` pass. Supply screenshots of reinforcement,
     combat and seat handoff for the owner's visual judgement (rule 20).
- **Hazards**: Route every placement through `apply`; do not calculate a second
  pool in the UI. New non-attack results have no attack outcome. Keep keyboard
  access, phase-specific hints and selection clearing coherent.
