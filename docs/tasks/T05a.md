- **Scope**: a seeded, deterministic `generateBoard(seed: number): { ok: true; map:
  GameMap } | { ok: false; errors: string[] }` that produces a `GameMap` meeting
  the **structural** invariants from `design/core-rules.md` § The board → What is
  fixed, on every draw from the seed:
  - 46 countries, 9 islands of sizes **3, 3, 3, 3, 5, 5, 7, 7, 10** (the design's
    sorted partition; T03's data file uses an unsorted partition, see below);
  - every country has 2 to 5 neighbours (borders + sea lanes), symmetric and
    free of self-loops, duplicates and dangling ends;
  - exactly **16** inter-island sea lanes (32 directed entries, each side
    naming the other, on a different island);
  - one connected graph (the border-plus-sea-lane graph spans all 46);
  - each island's bonus = `max(2, floor(size / 2) + entrances)`, where
    `entrances` is the number of that island's countries that border another
    island (decision 12, C-BON-02);
  - every country has a polygon of at least 3 points and a label point inside
    the map's bounds (placeholder geometry; T52 replaces it; C-BRD-06 says
    positions are display only).

  The **5 fairness checks** (bonus-out-of-proportion, fortress, easy-bonuses-
  concentrated, remote / hub island, crowded crossing country) are **T05b's**
  scope; T05a's generator is permitted to produce boards that fail any of them.
  Test for them anyway at the end as a documented *skipped* assertion (a
  `test.skip` with the T05b issue number) so the migration is mechanical.

  T03's `data/maps/archipelago.json` is a **sanity board**, not a reference
  output: the generator does not have to reproduce it. The T03 validator
  (`parseMap` + `tests/core/archipelago.test.ts`'s shape checks) must run on
  the generator's output unchanged. The generator's own test pins the **same
  structural constants** (multiset of island sizes, exactly 16 crossings,
  degree histogram, connected, bonuses by the rule) on every seed it draws.
  Names, polygons and country order are ours.
- **Done when**:
  1. `npx vitest run tests/core/board-gen.test.ts` passes; it fails on `main`
     today (the file does not exist).
  2. The suite asserts on at least 5 fixed seeds (e.g. 1, 2, 3, 7, 42):
     `generateBoard(seed)` returns `{ ok: true, map }`; `parseMap` accepts the
     `map` (round-trip through the existing reader); 46 provinces in 9
     islands whose sizes are a permutation of `[3,3,3,3,5,5,7,7,10]`; every
     province has 2 to 5 neighbours; the border-plus-sea-lane graph is
     connected; exactly 16 undirected inter-island crossings (32 directed,
     symmetric, off-island); every island's bonus equals
     `max(2, floor(size/2) + entrances)`.
  3. Determinism: two calls of `generateBoard(7)` produce deep-equal `GameMap`
     values (compare the `id`, `name`, every province's `id`/`island`/
     `borders`/`seaLanes`/`labelAt`/`polygon`, every island's `id`/`bonus`/
     `provinces`). Two calls of `generateBoard(s)` for 5 different `s` produce
     5 different boards (not deep-equal).
  4. The generator reads only from its `seed` argument; the `DeterministicRng`
     it constructs is its only random source; the file does not import or
     touch `Math.random`, `Date.now`, `performance.now`, `crypto`, `document`
     or `window`. The suite asserts the generator's `imports` (via
     `vitest --reporter=verbose --coverage` or a hand-rolled AST grep, see
     `tests/core/purity.test.ts`'s style) contain none of these names; or
     run the existing `tests/core/purity.test.ts` on `src/core/board-gen.ts`
     to confirm it passes the existing purity guard.
  5. Rule 9, shown in the PR: changing any one structural constant in the
     generator — the island-size constant array, the crossing target (16 →
     15 or 17), the degree min or max, the bonus rule's divisor (2 → 3) — or
     removing the `DeterministicRng` argument and reading from `Math.random`
     instead, fails the suite; applied, run, restored.
  6. `npm ci && npm run build && npx vitest run && npx playwright test` is
     green; `git status --porcelain tests/e2e` is empty (the UI did not
     move); `git status --porcelain src/ui` is empty;
     `git status --porcelain data/maps/archipelago.json` is empty (T03's
     data file did not move).
  7. `grep -c 'C-BRD-0[1-46]\|C-BON-02' src/core/board-gen.ts` prints at
     least 5: each constant cites the claim it traces to (rule 17). The
     T05b fairness-check claims are NOT cited here; they belong to T05b.
  8. `git status --porcelain src/core/index.ts` shows only the two added
     export lines (`board-gen`, `BoardGenResult`); no other `src/core/`
     file changed except `board-gen.ts` itself.
- **Hazards**: writing the algorithm to the predecessor's exact topology (rule
  19 — structural fidelity only; the generator must not reach for any
  original's data); running the generator off the game seed rather than its
  own argument (T05a is a pure function; the game-stream integration is
  T07's); checking fairness in this PR (T05b's scope; one of the 5 may need
  redesign once it is enforced and a counterexample arrives); a wall-clock or
  `Math.random` fallback "to be safe" (rule 18, the purity test will fail);
  reproducing T03's polygon order (display only; T52 owns layout); coupling
  to the deal (the generator returns a `GameMap`, not a `GameState`; the
  deal is T07+); leaving the design's "smallest-island-first" sorting
  implicit (write the constant array explicitly so the test can mutate it
  for rule 9).
