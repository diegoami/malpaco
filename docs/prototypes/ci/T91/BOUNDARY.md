# T91 frozen CI guard boundary

The owner approved consolidating T66/T67 and removing duplicate routine browser work. Main-authored policy tests are frozen; the implementer may append, never weaken them.

`tools/ci/policy.mjs` exports `classifyChanges(input)` returning `docs` or `full`, and `gatePass(input)` returning boolean. Input shapes and edge cases live in tests/tools/ci-policy.test.mjs. A classifier exception or missing/invalid metadata must select full verification. The prose allowlist is deliberately limited to README.md, RUN-NOTES.md, docs/ci-development.md, docs/tasks/*.md and docs/plans/**/*.md. Only added/modified entries qualify; no previous filename, deletions, renames, dot traversal or backslash paths.

The plan CLI must derive complete immutable paths from the actual checked-out PR merge commit, with HEAD matching event SHA and both parents matching event base/head. Use git name-status NUL output with --no-renames; uncertainty selects full. Every non-PR event is full. Never use PR-controlled filenames as shell code. CLI tests must exercise real temporary Git histories and malformed/mismatched event metadata.

The workflow has lightweight plan, conditional verify, and always-run stable ci aggregation; gate CLI must invoke gatePass with actual needs conclusions. Runtime code PR: complete npm test, package script (already builds/type-checks), extraction/checksums/HTTP acceptance, all existing release-config Playwright cases/projects once. Explicit workflow_dispatch full_release additionally runs source-server suite. No selectors, projects, retries, assertions or goldens are weakened. Local existing task Done-when commands remain binding.

Sparse checkout retains every runtime/test/fixture input and real commit provenance. Prefer broad text/code/data retention over brittle task lists; audit missing binary dependencies and any new extensions rather than silently excluding them. Do not combine explicit filter input with sparse-checkout. Concurrency is workflow+PR identity; non-PR groups use unique run_id. Future temporary screenshot/report retention may be bounded; durable release assets and retained proof must survive without deletion or history rewrite. Include failure reports from both ordinary and release output directories.

Verification must compare source/release browser inventories (case and project identities, not just counts), inspect actual workflow wiring, audit sparse inputs/required dependency hashes and package BUILD.json SHA against real HEAD, and retain measured counts/limits. No claimed speedup until one real final-head CI completes. For Goal2, document discovery, classification, fixture closure, required-name mapping, release mode, rollout, rollback and billing distinctions; adaptation is not a blind copy or permission to edit Goal2.
