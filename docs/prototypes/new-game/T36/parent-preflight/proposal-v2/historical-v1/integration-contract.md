# T36 proposed UI and service contract (unexecuted)

This contract guides the proposed e2e suite and host integration. It records decisions already supplied by the owner: one human plus three Normal computers remains the default; `view=reference-game` stays pinned; no `view` or an unknown `view` selects the geographic default; fixed-reference v2 loads into its identity's map inside the same shell; supported legacy generated saves keep their existing route/load behavior; T70 controls, totals, pause and log remain available.

## Service and host inputs

- The browser's expected geography is produced by the same public pure API used by game creation: `createGeographicGame(options, undefined, { attempts: T24.attemptsMax })`, with `boardGenerator={id:"geographic",version:1}`, rules `victory/1`, action schema 2. Tests statically import that API in the Playwright Node process and pass plain expected values into `page.evaluate`; they do not import `/src` in the browser, which would fail in extracted playable-artifact CI.
- The battle/map host receives the active map renderer factory, match identity/replay factory, options and initial state as one match context. Successful load constructs the matching context from the saved identity before replacing the current match. The same context seeds `GameEventHistory`. Map type is selected by explicit generator identity/version, never inferred from country IDs.
- Geographic play passes `state.map` directly to the renderer. T35 Q2048 coordinates normalize by `geography.unitsPerPixel` as documented in T35; no prototype or reference display coordinates replace them. Rule adjacency comes only from the map attached to the state.
- A bounded generation refusal returns its typed error/failure records without publishing partial `map`, `geography` or `state`; setup displays those classes/messages and can recover by entering a different seed. The UI setup controller shares its refusal rendering and retry path with the mount and accepts a create-game dependency; a UI unit test injects refusal then success using a render spy (no DOM package needed). Production exposes no URL flag, global test hook or mutable singleton for this test. The browser spec conditionally exercises the first measured real refusal if the 0–999 sweep contains one; if all seeds succeed, the browser assertion is skipped with that explicit reason and the injected typed branch is covered by the unit test.

## DOM contract consumed by acceptance

- Root: `#geographic-map`, an SVG with the map's own normalized bounds and an accessible name.
- Country: one `<g class="country">` per canonical country. `data-id` and `data-province` both identify its canonical ID; `data-owner` and `data-armies` always reflect the mounted state; selection and legal-target state have observable `data-selected`, `data-target`, `aria-pressed` values.
- Geometry and labels: `.cell` is the visible country polygon derived from that country's actual `state.map.provinces[].polygon`; `.name` is the visible label at the actual `labelAt`; `.badge` and `.count` are the visible owner marker and army count. Tests parse the `.cell` SVG path coordinates and compare them with `polygon / unitsPerPixel`, compare `.name` coordinates with `labelAt / unitsPerPixel`, and verify marker text/colors against `data-owner` / `data-armies`. There is no parallel `data-geometry` test-only payload.
- Route: `.lane` has `data-edge="<lexically-smaller-id>|<larger-id>"`, exactly one per sea adjacency, with drawable SVG points at the sidecar's actual route geometry. The acceptance parses route coordinates and compares them to `entranceReservations.points / unitsPerPixel`. Land border paint is similarly derived from actual map adjacency. `data-edge`, legal targets and core action validation all refer to the same map edge.
- Player totals use the existing T70 `[data-testid="player-army-total"]` contract inside the correct `[data-player]` row. Playback uses `#game-pause-button` and `#game-speed`; log uses `#game-log-button` and ordered `[data-event-index]` rows. Pause gates manual and automatic match-changing input while leaving save/load and log controls reachable.
- Save/load file input remains labelled `Load game`; serialized v2 payload carries generator, rules and action-schema identity. Geographic output uses geographic/1. A fixed-reference v2 upload renders the fixed-reference map under the same host shell; the save remains fixed-reference/1 on resave. A supported old generated v1 file is dispatched through its original generation/renderer path. Unsupported IDs or versions fail before replacing live DOM, URL, state, scheduler or event history.

## Acceptance split

`tests/e2e/geographic-board.spec.ts` checks the production default route, a bounded measured corpus, actual polygons and labels, two viewport projects, shared map adjacency, geographic save/load identity and T70 continuity. The test-runner statically computes expected state/maps. A separate small `tests/ui/geographic-game.test.ts` checks the injectable mount factory's refusal/error/retry and no-partial-mount behavior without browser flags or network hooks. Existing explicit reference fixtures, identity assertions and screenshots remain the reference compatibility proof.
